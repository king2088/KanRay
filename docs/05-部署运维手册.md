# 05 部署运维手册

面向运维。覆盖部署形态选型、Docker / systemd 部署、环境变量全表、数据库（存储后端）配置、Redis 配置、多实例分布式部署、密钥管理与安全加固、备份恢复。

> 事实源：本文变量名以 `backend/src/config/index.js` 为准；连接串与方言行为核对自 `backend/README.md` 与实测容器。

## 一、部署形态总览

| 形态 | 适用场景 | 元数据库 | Redis | 上传文件存储 |
|------|----------|----------|-------|--------------|
| **Docker compose 一键部署** | 单机快速体验、中小规模生产 | PostgreSQL（容器内卷） | 可选（见第六章示例） | 本地数据卷 `kanban_uploads` |
| **源码 + systemd** | 已有服务器 / 机房，需宿主级掌控 | 任意（sqlite 或外部库） | 可选 | 本地目录 |
| **多实例分布式** | 高可用 / 多副本横向扩展 | **仅外部库**（MySQL / PostgreSQL 等，**禁用 sqlite**） | 建议开启 | **共享存储（NFS / 对象存储）** |

> 一句话决策：单机选 Docker compose 最快；多副本/高可用必须把元数据库切到外部库并把上传目录做成共享存储，详见第七章。

## 二、Docker 一键部署

### 2.1 目录与文件

```
deploy/
├── deploy.sh            # 部署入口脚本
├── docker-compose.yml   # 四容器编排（postgres + backend(API) + worker(同步) + frontend(nginx)）
├── .env.example         # 环境变量模板
└── .env                 # 实际配置（首次运行自动生成）
```

前端为 Nginx 容器（`deploy/frontend/nginx.conf`）：直接托管构建产物，并把 `/api/` 反代到 `backend:3001`（`client_max_body_size` 32m，读超时 300s）。

### 2.2 子命令

```bash
./deploy.sh              # = up：构建并后台启动四容器
./deploy.sh up           # 同上
./deploy.sh down         # 停机（保留数据卷）
./deploy.sh down -v      # 停机并清除全部数据（-v 删卷，不可恢复！）
./deploy.sh restart      # 重启容器（保留数据）
./deploy.sh logs         # 跟随日志
./deploy.sh ps           # 容器状态
```

### 2.3 首次启动行为

1. 检测到无 `.env` 时，从 `.env.example` 复制并**随机注入三个密钥**：`JWT_SECRET`（base64 32B）、`DATASOURCE_SECRET`（base64 32B）、`POSTGRES_PASSWORD`（hex 24B）
2. `docker compose up -d --build` 构建并启动四容器（`postgres:16-alpine`、后端 API、同步 worker、前端 `nginx:1.27-alpine`；API 与 worker 共用同一镜像）
3. 后端首次启动自动**幂等建表**并创建种子管理员；compose 默认 `SYNC_MODE=worker`，同步由 worker 容器执行

启动后访问 `http://localhost:8080`（改 `deploy/.env` 的 `KANBAN_PORT` 可调整端口），Swagger 文档在 `http://localhost:8080/api/open/docs`。

### 2.4 deploy/.env 配置项（Compose 注入）

由 `docker-compose.yml` 读取并注入容器，模板见 `deploy/.env.example`；`POSTGRES_*` 仅容器间使用，不对外暴露。

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `KANBAN_PORT` | `8080` | 对外 HTTP 端口（frontend nginx 映射） |
| `POSTGRES_USER` / `POSTGRES_DB` | `kanban` / `kanban` | 元数据库账号与库名 |
| `POSTGRES_PASSWORD` | 随机（首次自动生成） | 元数据库密码 |
| `JWT_SECRET` | 随机（首次自动生成） | 用户令牌签名密钥 |
| `DATASOURCE_SECRET` | 随机（首次自动生成） | 数据源密码加密主密钥 |
| `ADMIN_INITIAL_PASSWORD` | `admin123` | 初始管理员密码（生产务必修改） |

### 2.5 三个数据卷

| 卷 | 挂载点 | 内容 |
|----|--------|------|
| `pgdata` | `/var/lib/postgresql/data` | 元数据库（PostgreSQL） |
| `kanban_data` | `/data` | 运行时数据目录（config.json 等） |
| `kanban_uploads` | `/uploads` | 上传的 Excel / CSV 文件 |

## 三、源码 + systemd 部署

适合已有服务器、离线内网或需要直接管理进程的场景。

### 3.1 环境要求

- Node.js ≥ 18（生产实测 `20-alpine`），npm
- 用 `systemd` 托管后端；前端构建产物用 Nginx 托管并反代 API

### 3.2 安装依赖

```bash
cd /opt/kanban/backend
npm ci --omit=dev          # 生产仅装运行依赖
```

### 3.3 配置环境变量文件

```bash
# /etc/kanban/backend.env（0600，含密钥请限制权限）
PORT=3001
JWT_SECRET=$(openssl rand -base64 32)
DATASOURCE_SECRET=$(openssl rand -base64 32)
ADMIN_INITIAL_PASSWORD=change-me-now
# DB_TYPE=postgres
# DB_URL=postgresql://kanban:kanban@127.0.0.1:5432/kanban?sslmode=disable
# REDIS_URL=redis://:pass@127.0.0.1:6379/0
```

> 后端**启动时不自动读取 `.env`**，需在 shell 中 export 或用 `EnvironmentFile`（见下）。全量变量见第四章。

### 3.4 systemd 单元

```ini
# /etc/systemd/system/kanban-backend.service
[Unit]
Description=Kanban Backend
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/kanban/backend
EnvironmentFile=/etc/kanban/backend.env
ExecStart=/usr/local/bin/node src/server.js
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now kanban-backend
systemctl status kanban-backend
```

### 3.5 前端构建 + Nginx

```bash
cd /opt/kanban/front-end
npm ci
npm run build              # 产物输出 front-end/dist
```

```nginx
# /etc/nginx/conf.d/kanban.conf
server {
    listen 80;
    server_name _;
    client_max_body_size 32m;

    root /opt/kanban/front-end/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout             10s;
        proxy_read_timeout                300s;
        proxy_buffering                   off;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 3.6 pm2 备选

```bash
npm i -g pm2
pm2 start src/server.js --name kanban-backend
pm2 save && pm2 startup
```

## 四、环境变量全表

### 4.1 配置优先级

**环境变量 > `config.json` > 默认值**。

`config.json` 读取顺序：`$DATA_DIR/config.json` → `backend/config.json`（示例见 `backend/config.example.json`）：

```json
{
  "db": { "type": "sqlite", "url": "", "sqlitePath": "data/kanban.db" },
  "cache": { "url": "" }
}
```

`db` 的三个字段与 `DB_TYPE` / `DB_URL` / `DB_PATH` 一一对应；`cache.url` 对应 `REDIS_URL`。

### 4.2 运行与目录

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3001` | 后端监听端口 |
| `DATA_DIR` | `backend/data` | 运行时数据目录；也是 `config.json` 首个读取位置（sqlite 默认文件所在目录） |
| `UPLOAD_DIR` | `backend/uploads` | 上传的 Excel / CSV 文件目录 |
| `TIMEZONE` | `Asia/Shanghai` | IANA 时区，前端按此时区渲染时间显示 |
| `NODE_ENV` | — | 生产置 `production`（Docker 镜像已内置） |

### 4.3 存储后端（元数据库）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DB_TYPE` | `sqlite` | `sqlite` / `mysql` / `mariadb` / `postgres` / `sqlserver` / `oracle` |
| `DB_URL` | 空 | 非 sqlite 时的 JDBC 风格连接串（示例见第五章） |
| `DB_PATH` | `data/kanban.db` | sqlite 文件路径（支持绝对路径） |
| `DB_POOL_MAX` | `10` | postgres / mysql 应用存储驱动的连接池上限；多副本部署时连接总数 = 副本数 × 此值 |

### 4.4 缓存与锁

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `REDIS_URL` | 空（关闭） | Redis 缓存/锁开关，如 `redis://:pass@127.0.0.1:6379/0`；空则用内存缓存 + 数据库租约锁（见第六章） |
| `CACHE_TTL_MS` | `60000` | 数据源目录缓存 TTL（毫秒） |

### 4.5 鉴权与密钥

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `JWT_SECRET` | `dev-secret-change-me` | 访问/刷新令牌签名密钥；**生产必须随机**，多实例必须一致 |
| `ACCESS_TTL` | `15m` | 访问令牌有效期（支持 ms/s/m/h/d） |
| `REFRESH_TTL_DAYS` | `7` | 刷新令牌有效期（天） |
| `ADMIN_EMAIL` | `admin@kanban.local` | 初始管理员邮箱（种子数据） |
| `ADMIN_INITIAL_PASSWORD` | `admin123` | 初始管理员密码；**生产必须修改** |
| `DATASOURCE_SECRET` | `kanban-dev-datasource-secret-32b!` | 数据源密码加密主密钥（AES-256-GCM 派生）；**生产必须随机 ≥32 字节，多实例必须一致**（见 8.2） |

### 4.6 上传与导入

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `MAX_FILE_SIZE` | `20971520` | 上传文件大小上限（字节，默认 20MB） |
| `MAX_ROWS` | `200000` | 导入数据集最大行数 |

### 4.7 同步调度

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SYNC_MODE` | `inline` | `inline`：调度与执行都在 API 进程内（单机/测试）；`worker`：API 只入队 `sync_jobs`，由独立 worker 进程消费执行（多副本/生产，见第七章） |
| `SYNC_SCHEDULER_INTERVAL_MS` | `60000` | 同步任务调度扫描间隔（毫秒）；`worker` 模式下即「到期配置入队」扫描间隔 |
| `SYNC_WORKER_POLL_MS` | `2000` | worker 进程领取 `sync_jobs` 的轮询间隔（毫秒） |
| `SYNC_MAX_CONCURRENT` | `2` | 并发同步任务上限（inline 为进程内并发，worker 为单进程领取并发） |
| `SYNC_DEFAULT_INTERVAL_SECONDS` | `86400` | 同步默认刷新周期（秒） |
| `SYNC_LOCK_TTL_MS` | `1800000` | 每次同步抢占锁 / 任务租约时长（毫秒，默认 30 分钟）；worker 崩溃后超过租约的任务可被回收重领 |

### 4.8 查询与性能

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `QUERY_MAX_GROUPS` | `10000` | 聚合查询在未显式指定分组上限时的分组数上限，防止超大分组结果全量物化；显式 `groupLimit` 优先 |

### 4.9 开放 API

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `OPEN_API_RATE_PER_MIN` | `120` | 开放 API 每 Key 每分钟限流 |
| `OPEN_API_MAX_ROWS` | `10000` | 开放 API 单次取数/聚合/看板导出最大行数（超出截断并返回 `truncated:true`） |

## 五、数据库（存储后端）配置

### 5.1 这是什么

`DB_TYPE` / `DB_URL` / `DB_PATH` 控制的是**元数据库**：用户 / 角色 / 权限 / 数据源配置 / 数据集 / 图表 / 看板 / 同步配置 `sync_configs` / 同步落库的本地物理表 `sync_*`。

与「外部数据源连接」是两码事：数据源连接密码加密存在各数据源记录里，查询/同步打到外部库，不随存储后端走。

### 5.2 支持的后端与连接串

| `DB_TYPE` | 驱动库 | 连接串示例 |
|-----------|--------|------------|
| `sqlite` | better-sqlite3 | `DB_PATH=data/kanban.db`（单文件） |
| `mysql` / `mariadb` | mysql2 | `mysql://root:Kanban%40123@127.0.0.1:13306/testdb` |
| `postgres` | pg | `postgresql://postgres:Kanban%40123@127.0.0.1:15432/testdb?sslmode=disable` |
| `sqlserver` | mssql | `mssql://sa:Kanban%40123@127.0.0.1:11433/testdb` |
| `oracle` | oracledb | `oracle://SYSTEM:Kanban%40123@127.0.0.1:11521/FREEPDB1` |

> 密码含特殊字符需做 URL 编码（如 `@` → `%40`）；`mariadb` 连接串协议可写 `mysql://`。

**快捷切换示例（PostgreSQL）**：

```bash
cd backend
# 方式一：环境变量（推荐，不落盘）
DB_TYPE=postgres DB_URL='postgresql://kanban:kanban@127.0.0.1:15432/kanban?sslmode=disable' npm start
# 方式二：config.json（backend/config.json，随部署持久化）
# { "db": { "type": "postgres", "url": "postgresql://kanban:kanban@127.0.0.1:15432/kanban?sslmode=disable" } }
```

### 5.3 首次启动会发生什么

1. 读取连接串，检查可达性；
2. 对所选库执行**幂等建表**（`IF NOT EXISTS` 等）+ **老库列补齐**（按方言探测已有表结构并补列）；
3. 若库中无管理员则自动播种 `admin@kanban.local`；
4. 直接进入正常使用，无需手工建表。

### 5.4 切换注意事项

- **不做存量数据自动迁移**：切换存储后端不会把旧库（如默认 SQLite）里的元数据自动搬运到新库。请在新库首次启动前决定部署形态，或用 `backend/scripts/` 下的工具/手工导出重建。
- **`DATASOURCE_SECRET` 必须一致**：历史数据源连接密码加密存储，密钥变更将无法解密（需逐个重新保存）。SKU 在创建首个数据源**之前**固定该密钥。
- **Oracle 事务语义**：Oracle 每语句自动提交，`transaction(fn)` 退化为逐条执行，批量写中途失败不会整体回滚；其余方言支持显式事务。
- **`sync_*` 物理表跟着存储后端走**：同步落库表建在存储后端库中，切换后端后随库移动/换库（旧表需自行迁移或重同步）。
- **本地实测容器**：`backend/scripts/datasource-live/docker-compose.yml` 提供六库存储后端实测栈（MySQL 13306 / MariaDB 13307 / PostgreSQL 15432 / SQL Server 11433 / Oracle 11521）。

## 六、Redis 配置

### 6.1 作用

1. **共享缓存**：当前覆盖数据源目录元数据 `catalogCache`（ETL 列元数据，TTL `CACHE_TTL_MS` 默认 60s）；RBAC 映射直接查库，不过缓存（权限变更即时生效）。
2. **分布式锁**：配 Redis 后，同步调度与并发写使用 `SET ... NX PX`（带持有者令牌的 Lua 释放脚本），多实例互斥更强。

### 6.2 开关与回退

- **开启**：设置 `REDIS_URL`（或在 `config.json` 的 `cache.url`）。URL 格式 `redis://[:password@]host:port/db`，TLS 用 `rediss://`。
- **不配 Redis（默认）**：缓存用进程内存 `Map`（带 TTL 惰性淘汰），锁用**数据库租约锁**（`sync_locks` 表，原子 `UPDATE ... WHERE locked_until < now`）——多实例共享同一元数据库即可互斥，**Redis 非必需**。
- **不依赖 Redis**：应用启动不依赖 Redis，未连接时自动降级内存缓存并打 warn 日志（不阻塞启动）。

```bash
REDIS_URL='redis://:mypass@127.0.0.1:6379/0' npm start
```

### 6.3 Docker compose 扩展示例（可选）

在 `deploy/docker-compose.yml` 中追加 Redis 服务，并为 backend 注入连接串：

```yaml
  redis:
    image: redis:7-alpine
    restart: unless-stopped

  backend:
    # ...原有配置...
    environment:
      REDIS_URL: redis://redis:6379/0
    depends_on:
      - redis
```

> 生产建议 Redis 设置密码并仅暴露内网；`redis:` 官方镜像默认无认证，仅是演示。

## 七、多实例 / 分布式部署

后端为**无状态多副本**设计（JWT 无状态、无 WebSocket/SSE、无需粘性会话），可横向扩展。前提清单如下。

### 7.1 前提条件

| # | 前提 | 说明 |
|---|------|------|
| 1 | **元数据库切到共享外部库** | `DB_TYPE=postgres`（或 mysql 等）+ 同一 `DB_URL`。**sqlite 是单文件单写者，严禁多实例共享** |
| 2 | **`JWT_SECRET` 全部一致** | 访问令牌是无状态签名，实例间不一致会互相拒签发 |
| 3 | **上传目录做成共享存储** | Excel/CSV 文件落在本地 `UPLOAD_DIR`；多副本需挂载同一 NFS / 对象存储，否则 A 实例接收的上传 B 实例读不到 |
| 4 | **建议配置 `REDIS_URL`** | 共享缓存 + Redis 锁；不配也能靠 `sync_locks` 表租约锁互斥 |
| 5 | **种子数据幂等** | 多实例同时启动安全：建表用 `IF NOT EXISTS`、资源用 `INSERT OR IGNORE`、管理员按邮箱查重 |

### 7.2 同步执行：inline 与 worker 两种模式

`SYNC_MODE` 决定同步在哪执行：

- **`inline`（默认）**：API 进程内调度 + 执行，适合单机 / 测试。多副本时每个实例都跑调度器，靠分布式锁互斥：
  - 未配 Redis：`sync_locks` 表租约锁（原子 UPDATE + 过期时间，`SYNC_LOCK_TTL_MS` 默认 30 分钟）；
  - 配了 Redis：`SET NX PX` 抢占；
  - 抢不到锁的实例打印 `[sync] cfg <id> 已由其它实例执行，跳过`；`runSync` 内部再以 `last_sync_status='running'` 二次幂等。
- **`worker`（生产推荐）**：API 只把到期配置写入 `sync_jobs` 队列表（`POST .../run` 也变为入队），由**独立 worker 进程/容器**消费执行。多副本下任务领取用 `sync_jobs` 行级条件 UPDATE 互斥，`lease_until` 租约保证 worker 崩溃后可回收重领。

两种模式都保证**任意时刻同一同步任务只有一个执行者**，无需 leader 选举。独立 worker 的好处：单列进程、同步失败/长任务不占用 API 事件循环，可按负载单独扩缩容。

worker 独立部署（与 API 共用镜像，仅入口不同）：

```yaml
  worker:
    build: { context: .., dockerfile: deploy/backend/Dockerfile }
    command: ["node", "backend/src/worker/main.js"]
    environment:
      DB_TYPE: postgres
      DB_URL: postgresql://kanban:kanban@postgres:5432/kanban
      SYNC_MODE: worker
      SYNC_MAX_CONCURRENT: "4"
    restart: unless-stopped
```

> worker 与 API 必须指向同一个元数据库；`SYNC_MODE` 在两侧都应设为 `worker`，否则 API 进程仍会在本地跑调度器。`deploy/docker-compose.yml` 已内置该服务。

### 7.3 健康检查与流量接入

```bash
curl http://<backend>:3001/api/health
# {"code":0,"data":{"status":"ok",...}}
```

前置负载均衡（Nginx / K8s Service）把 `/api/` 分发到多个 backend 副本即可；`trust proxy` 已开启，反代下 `X-Forwarded-*` 正常传递。

运行时可观测性快照（进程内聚合，无外部依赖）：

```bash
curl http://<backend>:3001/api/metrics
# 含 uptimeSeconds、eventLoop(p50/p99/max)、memory(rss/heap)、
# http(请求数/错误数/状态码分布/耗时直方图)、sync(同步次数/失败/行数/删除数)
```

> 若需限制访问，设置 `METRICS_TOKEN` 后须带 `X-Metrics-Token: <token>` 或 `?token=<token>`；未设置则与 `/api/health` 一样公开。压测脚本见 `backend/scripts/bench/http-bench.js`。

### 7.4 多副本示例（Docker compose）

```yaml
  backend:
    build:
      context: ..
      dockerfile: deploy/backend/Dockerfile
    environment:
      DB_TYPE: postgres
      DB_URL: postgresql://kanban:kanban@postgres:5432/kanban
      REDIS_URL: redis://redis:6379/0
      JWT_SECRET: ${JWT_SECRET}
      DATASOURCE_SECRET: ${DATASOURCE_SECRET}
      UPLOAD_DIR: /uploads   # 需替换为共享卷 / 对象存储挂载
    deploy:
      replicas: 3
```

或 `docker compose up -d --scale backend=3`。若启用 `SYNC_MODE=worker`，同步负载单独扩容：`docker compose up -d --scale worker=2`（任务领取由 `sync_jobs` 行锁互斥，不会重复执行）。

> 扩副本时注意连接总数：`副本数 × DB_POOL_MAX`（默认 10）不应超过元数据库 `max_connections`。

### 7.5 分布式部署的限制

- **开放 API 限流为每实例内存计数**（express-rate-limit 默认 store + `OPEN_API_RATE_PER_MIN`）。需要跨实例的严格全局配额时，须在网关层实现（本项目未内置共享限流存储）。
- 内存缓存是每实例各一份（配 Redis 后为共享）；对一致性影响仅限 TTL 内的目录元数据，可接受。
- 上传文件共享存储（NFS/对象存储）为多实例**必需项**，规划时勿遗漏。

## 八、密钥管理与轮换

### 8.1 JWT_SECRET

- 作用：签发/校验用户访问令牌与刷新令牌
- 轮换：修改后**所有存量登录态立即失效**，用户需重新登录（服务端刷新令牌按哈希存储）；多实例必须同步修改并滚动重启

### 8.2 DATASOURCE_SECRET

- 作用：派生 AES-256-GCM 密钥，加密外部数据源连接密码
- **必须在创建首个数据源之前固定**；变更会导致历史连接密码无法解密，需要逐一重新保存数据源密码
- 生产建议注入 ≥32 字节强随机值（`openssl rand -base64 32`）；多实例必须一致

### 8.3 泄露处置

- 访问令牌面上泄露 → 修改 `JWT_SECRET`（全量踢下线）或针对性禁用账号
- API Key 泄露 → 系统管理 → 开放 API → 停用/滚动/删除该 Key

## 九、备份与恢复

- 元数据均在元数据库中（Compose 场景为 Postgres 卷；源码模式为 sqlite 文件或所选外部库）。
- **Compose / Postgres**：
  - 在线备份：`docker compose exec postgres pg_dump -U kanban kanban > backup.sql`
  - 恢复：`./deploy.sh down --remove-orphans` → 重建卷 → `./deploy.sh up` → `docker compose exec -T postgres psql -U kanban kanban < backup.sql`
- **SQLite**：
  - 在线备份（推荐，一致性有保证）：`sqlite3 backend/data/kanban.db ".backup '/path/backup-kanban.db'"`
  - 或停服后直接复制 `kanban.db`；若此前运行过 WAL 模式，先确认 `-wal` 已 checkpoint，恢复时把 `kanban.db` + `-wal` 一起拷回（或删 `-wal`/`-shm` 取主文件）
- **恢复注意**：数据源同步落库表（`sync_*`）同样在元数据库中，随库一并备份/恢复。

## 十、安全加固与已知限制

### 10.1 安全加固清单

1. 修改初始管理员密码（`ADMIN_INITIAL_PASSWORD`）
2. 确认 `JWT_SECRET` / `DATASOURCE_SECRET` 为随机值（deploy.sh 首次会自动注入）
3. Redis 设置密码并仅暴露内网；数据库账号最小权限、关闭外网直连
4. 开放 API 凭证按最小权限授予，设置过期时间
5. 外部数据源账号遵循最小权限原则
6. 定期查看「操作审计」追溯变更
7. 分享链接口令强度 ≥4 位，按需停用失效链接
8. 置于反代/TLS 之后（`trust proxy` 已内置，需确保只信任可置信的代理）

### 10.2 已知限制

- **开放 API 限流**：每实例内存计数，多副本全局额度需网关层实现
- **sqlite 仅限单实例**：多实例部署必须切外部库
- 上传文件大小为本地盘存储，多实例需共享存储
- 分享创建时暂不支持自定义过期时间
- 文件型数据源不支持同步模式
- 单文件上传上限 20MB / 20 万行
- 增量默认开启主键对账删除（本地删除源端已删的行）；大表每次同步会多扫一遍源端主键，可在任务配置关闭（`reconcile_delete=0`）
- Oracle 存储后端 / Oracle 同步源：每语句自动提交，批量写中途失败不会整体回滚
- 开放 API 输出白名单：不返回构建 SQL / 表名 / 连接信息 / 密钥
