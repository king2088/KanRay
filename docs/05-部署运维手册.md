# 05 部署运维手册

面向运维。覆盖 Docker 一键部署、环境变量全表、存储后端切换、密钥管理与安全加固。

## 一、Docker 一键部署

### 1.1 目录与文件

```
deploy/
├── deploy.sh            # 部署入口脚本
├── docker-compose.yml   # 三容器编排（postgres + backend + frontend(nginx)）
├── .env.example         # 环境变量模板
└── .env                 # 实际配置（首次运行自动生成）
```

### 1.2 子命令

```bash
./deploy.sh              # = up：构建并后台启动三容器
./deploy.sh up           # 同上
./deploy.sh down         # 停机（保留数据卷）
./deploy.sh down -v      # 停机并清除全部数据（-v 删卷，不可恢复！）
./deploy.sh restart      # 重启容器（保留数据）
./deploy.sh logs         # 跟随日志
./deploy.sh ps           # 容器状态
```

### 1.3 首次启动行为

1. 检测到无 `.env` 时，从 `.env.example` 复制并**随机注入三个密钥**：`JWT_SECRET`（base64 32B）、`DATASOURCE_SECRET`（base64 32B）、`POSTGRES_PASSWORD`（hex 24B）
2. `docker compose up -d --build` 构建并启动三容器
3. 后端首次启动自动**幂等建表**并创建种子管理员

启动后访问 `http://localhost:8080`。

## 二、环境变量全表

### 2.1 deploy/.env（Compose 注入）

| 变量 | 说明 |
|------|------|
| `KANBAN_PORT` | 对外端口，默认 `8080` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | 元数据库连接（默认 kanban/随机/kanban），仅容器间使用 |
| `JWT_SECRET` | 用户令牌签名密钥（**生产必须随机**） |
| `DATASOURCE_SECRET` | 数据源密码加密主密钥（AES-256-GCM，**生产必须随机 ≥32 字节**） |
| `ADMIN_INITIAL_PASSWORD` | 初始管理员密码，默认 `admin123` |

### 2.2 backend 后端（源码运行时）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `ADMIN_EMAIL` | `admin@kanban.local` | 初始管理员邮箱 |
| `ADMIN_INITIAL_PASSWORD` | `admin123` | 初始管理员密码 |
| `JWT_SECRET` | `dev-secret-change-me` | 令牌签名密钥 |
| `ACCESS_TTL` | `15m` | 访问令牌有效期 |
| `REFRESH_TTL_DAYS` | `7` | 刷新令牌有效期（天） |
| `TIMEZONE` | `Asia/Shanghai` | 时区 |
| `OPEN_API_RATE_PER_MIN` | `120` | 开放 API 每 Key 每分钟限流 |
| `OPEN_API_MAX_ROWS` | `10000` | 开放 API 单次最大返回行数 |
| `SYNC_SCHEDULER_INTERVAL_MS` | `60000` | 同步任务调度扫描间隔（毫秒） |
| `SYNC_MAX_CONCURRENT` | `2` | 并发同步任务上限 |
| `SYNC_DEFAULT_INTERVAL_SECONDS` | `86400` | 同步默认刷新周期（秒） |
| `SYNC_LOCK_TTL_MS` | `1800000` | 同步锁最长持有时间（毫秒） |

> 源码运行需额外指定存储后端变量，见下节。

## 三、存储后端切换

### 3.1 支持的元数据库驱动

`DB_DRIVER=sqlite`（默认）/ `mysql` / `postgres` / `mssql` / `oracle`。

| 变量 | 说明 |
|------|------|
| `DB_DRIVER` | 驱动名 |
| `DB_HOST` / `DB_PORT` | 主机与端口 |
| `DB_NAME` | 库名 |
| `DB_USER` / `DB_PASSWORD` | 账号密码 |

示例（MySQL）：

```bash
DB_DRIVER=mysql DB_HOST=127.0.0.1 DB_PORT=3306 \
DB_NAME=kanban DB_USER=kanban DB_PASSWORD=xxx npm start
```

> 首次启动自动建表并种入默认管理员；迁移换代由后端幂等处理。
> 切换驱动时需要注意后端引号处理与别名大小写行为的差异（PostgreSQL 下已启用引用别名兼容）。

## 四、密钥管理与轮换

### 4.1 JWT_SECRET

- 作用：签发/校验用户访问令牌与刷新令牌
- 轮换：修改后**所有存量登录态立即失效**，用户需重新登录（服务端刷新令牌按哈希存储）

### 4.2 DATASOURCE_SECRET

- 作用：派生 AES-256-GCM 密钥，加密外部数据源连接密码
- **必须在创建首个数据源之前固定**；变更会导致历史连接密码无法解密，需要逐一重新保存数据源密码
- 生产建议注入 ≥32 字节强随机值（`openssl rand -base64 32`）

### 4.3 泄露处置

- 访问令牌面上泄露 → 修改 `JWT_SECRET`（全量踢下线）或针对性禁用账号
- API Key 泄露 → 系统管理 → 开放 API → 停用/滚动/删除该 Key

## 五、备份与恢复

- 元数据均在数据库（Compose 场景为 `deploy` 所在卷的 postgres 卷）
- 备份方式：容器停期间 `docker compose down` 后卷级备份，或 `docker compose exec postgres pg_dump -U kanban kanban > backup.sql`
- 恢复：`deploy.sh down` → 重建卷 → `deploy.sh up` → 导入 `psql`
- 数据源同步落库表同样在元数据库中，一并备份

## 六、安全加固清单

1. 修改初始管理员密码（`ADMIN_INITIAL_PASSWORD`）
2. 确认 `JWT_SECRET` / `DATASOURCE_SECRET` 为随机值
3. 开放 API 凭证按最小权限授予，设置过期时间
4. 外部数据源账号遵循最小权限原则
5. 定期查看「操作审计」追溯变更
6. 分享链接口令强度 ≥4 位，按需停用失效链接

## 七、已知限制

- 分享创建时暂不支持自定义过期时间
- 文件型数据源不支持同步模式
- 单文件上传上限 20MB / 20 万行
- 开放 API 输出白名单：不返回构建 SQL / 表名 / 连接信息 / 密钥
