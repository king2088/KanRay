# KanRay — 第一阶段需求清单

> 技术栈：**ExpressJS 5**（最新版 5.2.x，需 Node.js 18+）+ Vue 3 + Element Plus 前后端分离
> 目标定位：**单用户**下，让"小白"也能通过**本地上传 Excel** 完成「数据 → 图表 → 看板」的全流程 BI 低代码搭建
> 设计理念：借鉴业界 BI 平台的核心易用性理念，降低专业技术门槛

---

## 一、产品定位

第一阶段目标是做一个**给小白用的轻量级 BI 平台**。核心思想采用 **数据源 → 数据集 → 图表 → 看板** 四层模型，但对数据接入做了极大简化 —— 不需要配置数据库连接，只需要上传一个 Excel 文件即可开始。系统的本质是一个**纯展示/编排层**：数据由用户上传后存入系统，图表实时从系统内数据渲染，不在图表阶段隐藏 SQL 细节。

### 核心原则（贯穿本阶段所有需求）
1. **零配置上手**：全程无需编写任何代码或 SQL
2. **渐进式暴露**：小白默认看到拖拽/点选式向导，高级能力藏于折叠面板
3. **所见即所得**：图表配置实时预览，看板拖拽实时布局
4. **单用户优先**：本阶段不做登录/权限，架构上为第二阶段多用户预留抽象层

## 二、整体系统架构

```
┌────────────────────────────────────────────────────────────┐
│  前端（Vue 3 + Element Plus + Pinia + Vite）                 │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌───────────────┐     │
│  │ 数据管理 │ │ 图表构建 │ │ 看板编排 │ │ 看板查看(只读) │     │
│  └────┬────┘ └────┬────┘ └────┬────┘ └───────┬───────┘     │
│       │           │           │              │              │
│  ▲  RESTful HTTP (Express 5)                    │            │
├──┼─────────────────────────────────────────────┼────────────┤
│  后端（ExpressJS 5）                              │            │
│  ┌───────────┬───────────┬───────────┬─────────┴──────┐     │
│  │ 上传/解析   │ 数据集管理  │ 图表/看板  │ 查询/聚合引擎  │     │
│  │ Excel→数据 │ (语义层)   │ 存储      │ + 缓存         │     │
│  └─────┬─────┴───────────┴───────────┴────────┬──────┘     │
│        │                                      │             │
│  ┌─────┴──────────────────────────────────────┴──────┐      │
│  │                 持久化存储（SQLite/文件）             │      │
│  └──────────────────────────────────────────────────┘      │
└────────────────────────────────────────────────────────────┘
```

### 技术选型说明
| 层面 | 选择 | 理由 |
|------|------|------|
| 后端框架 | ExpressJS 5 | 用户指定，异步 await、原生 Promise 错误处理更友好 |
| 前端框架 | Vue 3 (Composition API) + Vite | 用户指定，生态成熟 |
| UI 组件库 | Element Plus | 用户指定 |
| 前端状态 | Pinia | Vue3 官方推荐 |
| 数据存储 | SQLite（通过 better-sqlite3 或 Prisma） | 第一阶段单机足够，零部署成本 |
| Excel 解析 | 后端 `xlsx`(SheetJS) 或 `exceljs` | 上传后服务端解析 |
| 图表渲染 | 前端 Apache ECharts（Vue 封装） | 生态成熟，图表类型丰富，社区维护活跃 |
| 看板布局 | 前端 `vue-grid-layout` (可选) 或自研 grid | 拖拽 / 缩放 / 排序 |
| API 校验 | zod / joi | Express 5 路由去掉了内联正则，参数集中校验 |

### Express 5 技术约束（落地时需遵循）
- 路由路径语法采用新规则（可选段 `{/x}`、通配符需命名 `*splat`、禁用内联正则）
- 路由参数校验放 handler 内用 zod/joi 完成
- `req.body` 不再默认 `{}`，需显式检查
- 异步 handler 通过 `async` 抛错自动交给错误中间件（可省去 try/catch 样板）
- 推荐用 `app.use(express.json())` + `app.use(express.urlencoded({ extended: true }))` 分开注册
- Node.js 版本要求 ≥ 18

## 三、功能需求模块

> 优先级标记：**P0** = 必须，第一版核心；**P1** = 应有，体验关键；**P2** = 可选增强

### 3.1 数据模块：Excel 上传与解析（P0）

参考业界 BI 平台的"数据库/数据集"层，但用文件上传替代数据库连接。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| D-01 | 上传 Excel 文件（.xlsx / .xls / .csv） | P0 | 拖拽上传 + 文件选择，展示上传进度 |
| D-02 | 服务端解析并**预览前 N 行**（如 50 行） | P0 | 无需入库即可预览，辅助字段类型确认 |
| D-03 | **字段类型自动识别** | P0 | 自动推断每列类型：文本/整数/小数/日期/布尔，允许用户手工修改 |
| D-04 | 字段元数据维护 | P0 | 可重命名字段、设置展示别名/备注，标记是否参与聚合 |
| D-05 | 数据落库为"**数据集 (Dataset)**" | P0 | 每个 Excel 成为一个数据集，持久化存储 |
| D-06 | 数据集列表管理 | P0 | 列表展示、搜索、重命名、删除、复制 |
| D-07 | 数据预览与分页 | P0 | 查看数据集内的数据行，可切换显示列、排序 |
| D-08 | 大文件/大行数限制与提示 | P1 | 设置行数/大小上限（如 20 万行 / 20MB），超限友好提示 |
| D-09 | 数据类型转换与清洗 | P2 | 空值处理策略、去除重复行、格式统一 |
| D-10 | 上传历史记录 | P2 | 记录每次上传的时间/文件名/行数 |

**验收要点**：小白上传任意一个常见 Excel 后，能在 3 步内把它变成一个可选的数据集，并能看到字段类型和预览数据。

### 3.2 图表模块（P0）— 无代码图表构建

这是"低代码"的核心，把 **维度 + 指标 + 图表类型** 模型简化为向导式界面。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| C-01 | 选择数据源（数据集） | P0 | 从已创建的数据集中选择 |
| C-02 | **图表类型选择**（带图标/缩略图，可搜索） | P0 | 首批图表：柱状、折线、饼图、环形、条形、表格、仪表盘 Gauge、数值/统计卡、雷达图、漏斗图 |
| C-03 | **字段拖拽到"维度"与"指标"** | P0 | 维度放 X轴/分类，指标放 Y轴/数值，含聚合方式（求和/平均/计数/最大值/最小值/去重计数） |
| C-04 | **实时预览面板** | P0 | 配置右侧实时渲染图表，改动立即生效 |
| C-05 | 筛选条件（Filter）配置 | P0 | 设置静态筛选（如只显示某分类） |
| C-06 | 分组/排序/是否展示数据标签 | P0 | 基础展示控制 |
| C-07 | 图表样式定制 | P1 | 标题、颜色主题、图例位置、轴线、Tooltip |
| C-08 | 图表保存/命名/覆盖 | P1 | 保存为图表模板，可复用 |
| C-09 | 图表列表管理与复用 | P1 | 展示所有已存图表，可再次编辑/复制/删除 |
| C-10 | 时间序列支持 | P1 | 日期字段作为 X 轴，支持时间粒度（日/周/月/年）聚合 |
| C-11 | 多指标对比 | P1 | 一张图展示多维 + 多指标（系列） |
| C-12 | 图表"高级分析" | P2 | 滚动平均/移动平均、同比/环比、趋势线 |
| C-13 | 数据下钻（Drill Down） | P2 | 点击图表某一段查看明细数据 |
| C-14 | 图表导出（PNG/CSV） | P2 | 导出图表图片或数据 |

**验收要点**：小白在"选数据集 → 选图表 → 拖两个字段 → 点保存"这条路径上，全程无需写 SQL/代码，即可完成一个统计图表。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|

| K-04 | **看板级通用筛选器（Filter）** | P0 | 在看板顶部放置筛选器（如日期、某个分类字段），**联动过滤看板内所有关联图表** —— Native Filter 模式 |

### 3.4 查询 / 聚合引擎（P0）— 后端核心，数据查询与缓存

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| Q-01 | 通用聚合查询接口 | P0 | 接收"数据集 + 维度 + 指标 + 聚合 + 筛选 + 分组/排序"，返回聚合结果 |
| Q-02 | 维度/指标语义层 | P0 | 后端维护字段元数据，图表层只传逻辑字段名，不直接写 SQL |
| Q-03 | 时间粒度聚合 | P1 | 日期按日/周/月/年桶化 |
| Q-04 | 结果缓存 | P1 | 相同查询参数命中缓存，降低计算压力（Redis 缓存设计） |
| Q-05 | 大结果集限制/分页 | P1 | 聚合结果上限保护，防止前端卡死 |
| Q-06 | 查询统计与慢查询标识 | P2 | 记录查询时长，为性能优化提供依据 |
| Q-07 | 查询 API 版本化与抽象 | P1 | 数据访问层抽象，为将来接入真实数据库（第二阶段）预留统一接口 |

> 架构关键点：查询引擎必须抽象出统一的"**数据提供者(DataProvider)**"接口。第一阶段实现"ExcelProvider"（从 SQLite 查）；第二阶段可无缝新增"SQLDatabaseProvider"。这样图表/看板层完全不用改，为产品化扩展铺路。

```
主界面（侧边栏导航）
├── 📁 数据管理
```

## 五、MVP 四步核心流程（验收主线）

1. **建数据**：上传 `销售数据.xlsx` → 系统自动识别字段类型 → 保存为数据集
2. **建图表**：选择该数据集 → 选"柱状图" → 拖「月份」到维度、拖「销售额」到指标 → 实时看到柱状图 → 保存
3. **编看板**：新建看板 → 把刚才的柱状图 + 一个饼图拖入画布 → 添加日期筛选器 → 保存
4. **看看板**：进入查看模式，切换日期筛选器，所有图表同步联动刷新

## 七、验收标准（Definition of Done）

1. 一个零基础用户，在不看文档的前提下，能独立完成「上传 Excel → 建图 → 排看板 → 加筛选联动」全流程
2. 后端仅依赖 ExpressJS 5，API 遵循 RESTful 规范且返回统一结构（`{ code, data, message }`）
3. 数据访问通过 DataProvider 抽象，能清晰替换为数据库实现（为第二阶段预留）
4. 图表使用 ECharts 渲染，看板支持拖拽布局与筛选联动
5. 所有异步错误经 Express 5 自动进入统一错误中间件，不会导致进程崩溃
