# 应用存储可选 + 数据源同步模式 设计文档

- **日期**：2026-09-14
- **关联**：承接 M3（22 驱动注册表 / 协议族 Provider / SqlDataProvider / 数据集构建器）
- **状态**：设计已评审，待实施

## 1. 目标与背景

当前系统自身的数据一律落在 `backend/data/kanban.db`（better-sqlite3，同步裸 SQL），用户/角色/图表/看板/数据源注册/上传数据集数据行全部在此。两件事需要落地：

1. **应用存储可选**：部署时通过 JSON 配置把系统自身存储（元数据 + 上传数据集数据行）换成 MySQL / MariaDB / PostgreSQL / SQL Server / Oracle 之一，SQLite 保持默认零配置。
2. **数据源同步模式**：数据源新增「存储方式」——`direct`（直连，现行行为不变）与 `sync`（把外部库表周期性同步进应用所选存储库），同步表仅作为物理表落库，不自动注册数据集，用户可手动注册。

### 消费模型与边界

- 六个 OLTP 库为系统存储候选：`sqlite`（默认）/ `mysql` / `mariadb` / `postgres` / `sqlserver` / `oracle`。
- ClickHouse / Doris **不作为应用元数据存储**（OLAP 无事务/外键/行级 UPDATE，OLTP 语义不匹配）；预留为 `sync_configs.target_type='olap'` 的同步目标（本期只实现 `app`，`olap` 仅写进模型与接口契约，不实现）。
- 同步表落所选 OLTP 库（`target_type='app'`）。
- **不做存量迁移**：切新库即从干净库起跑；服务启动幂等建表 + 种子。
- 数据规模沿用 `MAX_ROWS`（默认 20 万行/表）作为同步行数守门。

## 2. 功能范围

### 2.1 应用存储可选

- 配置：`backend/config.json`（不入库，提供 `backend/config.example.json`），加载优先级 `默认值 < config.json < 环境变量`。
- 支持三处连接描述：`DB_TYPE` / `DB_URL`（mysql|mariadb|postgres|sqlserver|oracle 连接串）/ `sqlitePath`（或 `DB_PATH`）。
- 服务启动幂等引导：分方言建全部元数据表（含新旧列管理）+ 上传数据表 DDL + 种子（内置角色/权限/管理员）。

### 2.2 数据源同步模式

- `data_sources` 增列 `mode`：`direct`（默认）/ `sync`。
- 同步型数据源的库表浏览：表行提供「同步」操作，配置对话框字段：
  - 目标表名（可选，默认以 `sync_${datasourceId}_${源表名}` 生成，保证应用共享存储库中跨数据源不撞名；需通过标识符白名单元数据）；
  - 同步策略 `full` / `incremental`；
  - 增量时必填**水印字段**（从 `listColumns` 的 numeric/date 列中选择）、可选**主键字段**；
  - 刷新周期（秒，默认 24h）；
  - 本地落库目标 `target_type='app'`（本期仅此值）。
- 触发：保存即执行首同步；之后由调度器按期执行；支持前端手动「立即同步」。
- **首同步不注册数据集**：同步结果只落物理表；之后用户在该同步数据源中手动 `register-table` 注册为数据集（复用现有链路，`source_type` 仍为 `sql`）。
- 同步任务展示：数据源详情页列每张同步表的最近状态 / 下次刷新时间 / 最近一条日志。

## 3. 架构总览

```
配置层(src/config/index.js) → 选择存储类型
        │
        ▼
存储适配层 src/db/
  index.js      统一异步门面（run/all/get/exec/transaction/idOf + prepare() 兼容形态）
  drivers/      sqlite.js / mysql.js (含 mariadb) / postgres.js / sqlserver.js / oracle.js
  ddl/          每方言一份幂等 DDL + 启动列检测（columnInfo/addColumn）
        │
        ├── 服务层 117 处 db.prepare(...).run/all/get 调用 → 只补 await，SQL 不变
        ├── 上传数据集：ensureDatasetTable 方言化建表 + 批量 INSERT（分批）
        └── 查询引擎：上传数据聚合/分页/计数统一走 build-sql.js 方言生成器
                              ▲
                              │
同步链路 src/jobs/sync-scheduler.js + services/sync.service.js
   外部源 providers.runQuery(listColumns) → (增量/全量) → 应用存储库落表 + sync_logs
```

## 4. 详细设计

### 4.1 配置层

```jsonc
// backend/config.example.json
{
  "db": {
    "type": "sqlite",                // sqlite | mysql | mariadb | postgres | sqlserver | oracle
    "url": "",                       // 如 postgresql://user:pw@127.0.0.1:5432/kanban
    "sqlitePath": "data/kanban.db"
  }
}
```

读取规则（`src/config/index.js` 扩展）：

1. 读取 `backend/config.json`（不存在则用默认）；
2. 环境变量覆盖：`DB_TYPE`、`DB_URL`、`DB_PATH`、`DATA_DIR` 等原有变量继续生效；
3. 无效 `DB_TYPE` 时启动报错并给出支持清单。

### 4.2 存储适配层

统一异步门面，保留 `db.prepare(sql)` 兼容形态（返回 async 的 `{ run, all, get }`），服务层改动降至"补 `await`"。

| 方法 | 语义 | 方言差异收敛点 |
| --- | --- | --- |
| `run(sql, params)` | 写操作 | returns `{ changes, id }`：id 由 `lastInsertRowid` / `RETURNING id` / `insertId` / `SCOPE_IDENTITY()` / `RETURNING id` 产生 |
| `all/get(sql, params)` | 读 | 占位符 `?` → `$n`(pg) / `?`(mysql/mariadb) / `@pN`(mssql) / `:1`(oracle)；Oracle 列名转小写 |
| `exec(sql)` / `execBatch(sqls)` | DDL/批量 | mssql/oracle 无多语句 exec → 逐条执行 |
| `transaction(fn)` | 事务 | mysql/oracle 需手动 BEGIN/COMMIT；pg/mssql 自带 |
| `init()` | 幂等建表+种子 | 每方言 DDL 独立文件，`CREATE TABLE IF NOT EXISTS` + 列存在性检测补 `ALTER` |
| `close()` | 关闭池 | — |

DDL 方言差异集中表：

| 项 | sqlite | mysql/mariadb | postgres | sqlserver | oracle |
| --- | --- | --- | --- | --- | --- |
| 主键自增 | `INTEGER PRIMARY KEY AUTOINCREMENT` | `AUTO_INCREMENT` | `SERIAL`/`BIGSERIAL` | `IDENTITY(1,1)` | `NUMBER GENERATED BY DEFAULT AS IDENTITY` |
| 文本 | `TEXT` | `TEXT`/`VARCHAR(255)` | `TEXT` | `NVARCHAR(MAX)` | `VARCHAR2(4000)` |
| 时间默认 | `datetime('now')` | `DEFAULT (NOW())` | `DEFAULT now()` | `DEFAULT SYSDATETIME()` | `DEFAULT SYSTIMESTAMP` |
| 布尔 | `INTEGER` 0/1 | `TINYINT` | `BOOLEAN` | `BIT` | `NUMBER(1)` |
| 列检测 | `PRAGMA table_info` | `SHOW COLUMNS FROM` | `information_schema.columns` | same | `ALL_TAB_COLUMNS` |
| 标识符引用 | `"col"` | `` `col` `` | `"col"` | `[col]` | `"COL"` |

`ensureDatasetTable`（上传数据表）与 `build-sql.js` 的方言生成（聚合/分页 wrapped/limit/count）都是既有的"M 方言已覆盖 mysql/pg/mssql/oracle/clickhouse"能力，直接复用；sqlite 作为方言族加入 `dialects.js`（标识符引用 `"`、`?` 占位、`LIMIT`）。

### 4.3 种子与旧库引导

`seeds.js` 改走参数化门面写法；启动 `init()` 后幂等插入内置权限点/角色/管理员（沿用现有判定逻辑，数据库无关）。

### 4.4 同步模式

**数据模型**

```sql
-- data_sources 增列
ALTER TABLE data_sources ADD COLUMN mode TEXT NOT NULL DEFAULT 'direct';

CREATE TABLE IF NOT EXISTS sync_configs (
  id INTEGER PK AUTO,
  datasource_id INTEGER NOT NULL REFERENCES data_sources(id) ON DELETE CASCADE,
  source_schema TEXT,
  source_table TEXT NOT NULL,
  local_table TEXT NOT NULL,
  target_type TEXT NOT NULL DEFAULT 'app',      -- app | olap(预留)
  strategy TEXT NOT NULL DEFAULT 'incremental', -- full | incremental
  watermark_field TEXT,
  watermark_kind TEXT NOT NULL DEFAULT 'id',    -- id | time
  primary_key TEXT,
  sync_interval_seconds INTEGER NOT NULL DEFAULT 86400,
  last_sync_at TEXT, last_watermark TEXT,
  last_sync_status TEXT,                        -- success | failed | running
  last_sync_msg TEXT,
  created_at/updated_at
);

CREATE TABLE IF NOT EXISTS sync_logs (
  id INTEGER PK AUTO,
  sync_config_id INTEGER NOT NULL REFERENCES sync_configs(id) ON DELETE CASCADE,
  started_at TEXT, finished_at TEXT,
  status TEXT, rows_synced INTEGER, message TEXT
);
```

**同步执行（`src/services/sync.service.js`）**

1. 取源：`listColumns` 校验水印/主键存在且类型合法（白名单元数据，无自由拼接）。
2. 拉取：`providers.runQuery(cfg, bufferedSQL)`
   - 全量：`TRUNCATE`（或 DROP+CREATE 重建，避免方言差异）本地表后分批 `INSERT`；
   - 增量：`SELECT ... WHERE 水印 > lastWatermark ORDER BY 水印 ASC`，keyset 分批；
     - 有主键 → `build-sql.js` 新增 `buildUpsert(dialect, ...)`：mysql `ON DUPLICATE KEY UPDATE`、pg/sqlite `ON CONFLICT(pk) DO UPDATE`、mssql/oracle `MERGE`；
     - 无主键（追加型）→ 纯分批 INSERT；
     - 每推进一批即更新 `last_watermark`；向提交事务、任一失败回滚。
3. 行数守门：单表 > `MAX_ROWS` 即中止并 `failed`，防失控。
4. 每条任务执行写 `sync_logs`；更新 `sync_configs.last_sync_*`。

**调度器（`src/jobs/sync-scheduler.js`）**

- 进程内 `setInterval` 心跳（60s）：扫描 `due = last_sync_at + interval ≤ now` 且非 running 的配置；
- 全局并发上限（默认 2）、单表互斥（进程内 running 集合）；
- 多实例部署需分布式锁，明确**本期不支持**（属 M4 多租户里程碑）。

**接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/datasources/:id/sync-configs` | 新建同步配置（立即触发首同步） |
| GET | `/api/datasources/:id/sync-configs` | 同步任务列表（含状态/下次刷新） |
| PATCH | `/api/datasources/:id/sync-configs/:cid` | 修改周期/策略等（需重同步时全量重建） |
| DELETE | `/api/datasources/:id/sync-configs/:cid` | 停用并删除本地表（可选项 `keep_table`） |
| POST | `/api/datasources/:id/sync-configs/:cid/run` | 手动立即同步 |
| GET | `/api/datasources/:id/sync-configs/:cid/logs` | 同步日志分页 |

同步型数据源的库表浏览接口复用 `/:id/schemas`、`/:id/schemas/:schema/tables`、`register-table`，但路由在 `mode='sync'` 时指向"应用存储库中该数据源的本地表集合"。

### 4.5 前端

- DataSourceFormDialog：新增「存储方式」单选 `direct`（现行表单不变）/ `sync`（连接配置同直连，另提示创建后需在详情页配置同步表）。
- 数据源详情页（`DataSourceDetail.vue`）：
  - `direct`：现行浏览行为；
  - `sync`：库表浏览区 + 每张表「同步」按钮 → 配置弹窗（策略/水印/主键/周期/目标表名/数据集名不涉及——本版不自动注册）；
  - 「同步任务」区块：各同步表状态/下次刷新/日志入口/「立即同步」按钮。
- 手动注册数据集仍走现有 `register-table` 弹窗，目标表选本地同步表即可（`source_type='sql'`）。

## 5. 错误处理

- 配置 `DB_TYPE` 非法或数据库连接失败：启动即抛出明确错误（含可选项清单），不静默回退 SQLite。
- 同步失败：`skip_if_running` + 上次失败不阻塞定时；日志记录错误；前端任务状态展示 `failed` 与 `message`。
- 超时/断连：沿用各 provider 的超时配置与重试策略（外部源侧），本地落库侧走事务回滚。

## 8. 已知限制 / 不做

- 不做存量 SQLite→目标库迁移（全新部署）
- `target_type='olap'`（ClickHouse/Doris 同步目标）仅契约预留，本期不实现
- 多实例部署的分布式同步锁不支持（M4）
- 增量删除行不同步（仅上插/更新）；全量可覆盖
- Oracle 标识符 ≤30 字节限制（本项目表名列名均在限内）
